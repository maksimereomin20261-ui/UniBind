# UniBind — исходники и черновик установщика

Это подготовленная, но не проверенная на Windows версия. Не публикуйте её как стабильный релиз до проверки работы приложения, установщика, WebView2, ярлыка и обновления на Windows 11.

## Устройство
- `app/` — исходники биндера и его ресурсы.
- `installer/launcher.py` — окно установки и обновления; собирается в один EXE.
- `.github/workflows/build.yml` — сборка на Windows в GitHub Actions: вручную или при изменении исходников. Она **не создаёт и не публикует релиз**.
- `.github/workflows/publish-update.yml` — ручной выпуск тестового обновления одной кнопкой; автоматически запускает сборку и проверки до публикации.

При запуске EXE проверяет последний опубликованный GitHub Release репозитория `maksimereomin20261-ui/UniBind`, ищет `UniBind-App.zip`, загружает его и сверяет SHA-256 с метаданными GitHub. Это проверка целостности, не цифровая подпись автора. Установщик не скачивает и не устанавливает WebView2 Runtime автоматически; если он не обнаружен, показывается предупреждение и адрес официальной страницы.

Пакет приложения устанавливается в `%LOCALAPPDATA%\UniBind\versions`, данные — в `%LOCALAPPDATA%\UniBind\data`, ярлык запускает загрузчик. Обновления проверяются при запуске через ярлык; при сетевой ошибке или ошибке установки запускается прежняя версия. После запуска приложения загрузчик удаляет старые папки версий с именами-хешами, если в них нет дополнительных файлов. Если в старой папке найдены личные данные, она сохраняется; данные, настройки и бинды в отдельной папке также не удаляются. После очистки автоматический откат к удалённой версии недоступен. Изменения самого загрузчика существующие ярлыки автоматически не получают: для него потребуется отдельный механизм обновления.

Старые профили не переносятся автоматически. Сохраните исходный архив; импорт данных нужно проверить отдельно. При прямом запуске исходника без `UNIBIND_DATA_DIR` файлы пользователя, как и прежде, создаются рядом с приложением.

## Как собрать черновик
1. Загрузить проект на GitHub, включая папку `.github`.
2. В Actions выбрать `Собрать UniBind (без публикации)` → Run workflow. Скачайте artifact `UniBind-Windows-unverified`. Компиляция — не тест приложения.
3. Для работы загрузчика в будущем релизе должен лежать **в корне релиза** файл `UniBind-App.zip`, а для пользователей — `UniBind_Setup.exe`. Имена менять нельзя. Пока не публикуйте их без проверки.
4. Для каждого обновления приложения создать новый Release и прикрепить новый `UniBind-App.zip`. Последним считается GitHub latest release, не draft/prerelease. Старый релиз v1.0.0 использует другое имя пакета и не подойдёт.

Сборка получает официальный AutoHotkey 2.0.31 и Ahk2Exe 1.1.37.02a2 с закреплённой SHA-256 проверкой. Windows WebView2 Runtime нужен отдельно. Не включайте личные `config`, `logs`, `backups` в публичный репозиторий и релиз. `.gitignore` не удаляет из истории Git уже опубликованные файлы.

## Как менять биндер и выпускать обновление

Можно попросить помощника изменить код и выпустить обновление. Либо отредактируйте исходники на GitHub: основной код — `app/UniBind.ahk`, интерфейс — `app/ui/`, загрузчик — `installer/launcher.py`. Не загружайте личные конфиги, бинды и резервные копии.

Изменения в репозитории не публикуются пользователям автоматически. Чтобы выпустить текущую ветку `main`:

1. Откройте [кнопку выпуска UniBind](https://github.com/maksimereomin20261-ui/UniBind/actions/workflows/publish-update.yml).
2. Нажмите **Run workflow**, проверьте, что выбрана ветка **main**.
3. Для настоящего выпуска оставьте флажок **«Пробный запуск: не публиковать обновление»** выключенным и нажмите зелёную кнопку **Run workflow**. Если только проверяете процесс, включите этот флажок: релиз не будет создан.
4. Дождитесь результата. Запуск автоматически соберёт программу и проведёт тесты установщика на Windows. Если возникнет ошибка, проверьте раздел Releases и журнал Actions перед повторным запуском.
5. При успехе создаётся новый публичный тестовый GitHub Release, выбранный как latest. При следующем запуске через ярлык загрузчик проверит его и установит новый пакет приложения. Не публикуйте выпуск как стабильный без отдельной проверки биндера на реальном Windows 11.

Пробный прогон процесса без публикации прошёл; создание релиза именно этим workflow пока не проверяли целиком.

Сам установленный загрузчик пока не обновляется автоматически. Если изменился `installer/launcher.py`, существующим пользователям нужно один раз скачать новый `UniBind_Setup.exe`, закрыть UniBind и запустить его. Для обычных изменений биндера повторно скачивать Setup не требуется.

## Тестирование перед публикацией
Закрыть все экземпляры; проверить первое включение и настройку, резервную копию и импорт существующих профилей, повторный запуск и обновление, отсутствие интернета, ошибку и повреждение скачанного файла, ограничение одновременных запусков, ярлык на обычном и перенаправленном рабочем столе, WebView2, обработку SmartScreen, работу с игрой. См. `app/RELEASE_CHECKLIST.md`; старые файлы документации сборки относятся к исходному проекту и могут не описывать этот загрузчик.
